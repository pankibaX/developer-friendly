📌 1. Concept Covered
Spring AOP dynamic proxies: Declarative annotations like @Transactional, @Async, and @Secured work via proxy interception and are completely bypassed during internal method self-invocation.
❓ 2. Question
In OrderProcessingService, a client calls submitOrder(), which internally invokes this.executePayment() annotated with @Transactional(propagation = Propagation.REQUIRES_NEW).

Why is the @Transactional annotation on executePayment() completely ignored, and how do you cleanly architect this to enforce transaction boundaries?
💻 3. Code Challenge
import org.springframework.stereotype.Service; import org.springframework.beans.factory.annotation.Autowired; import org.springframework.transaction.annotation.Transactional; import org.springframework.transaction.annotation.Propagation; @Service public class OrderProcessingService { @Autowired private OrderRepository orderRepository; @Autowired private PaymentClient paymentClient; public void submitOrder(Order order) { order.setStatus(OrderStatus.PENDING); orderRepository.save(order); executePayment(order); // Internal self-invocation } @Transactional(propagation = Propagation.REQUIRES_NEW) public void executePayment(Order order) { paymentClient.charge(order.getCustomerId(), order.getAmount()); order.setStatus(OrderStatus.CONFIRMED); orderRepository.save(order); } }
🎯 Answer Quality:
Not Rated
Answer Key & Deep-Dive Explanation

Root Cause: Spring uses runtime proxies (CGLIB subclasses or JDK dynamic proxies) to intercept calls and apply cross-cutting logic like transactions and security. When an external client calls a bean method, it invokes the proxy.

However, when submitOrder() invokes executePayment() directly via this, the call executes on the raw target object, bypassing the Spring proxy interceptor chain entirely. Therefore, @Transactional is never triggered and the method runs in standard auto-commit mode without transaction management.

Recommended SolutionJava
// Clean Architectural Fix: Decompose into cohesive domain services
@Service
public class OrderProcessingService {
    private final OrderRepository orderRepository;
    private final OrderPaymentService orderPaymentService;

    public OrderProcessingService(OrderRepository orderRepository, OrderPaymentService orderPaymentService) {
        this.orderRepository = orderRepository;
        this.orderPaymentService = orderPaymentService;
    }

    @Transactional
    public void submitOrder(Order order) {
        order.setStatus(OrderStatus.PENDING);
        orderRepository.save(order);
        orderPaymentService.executePayment(order); // Invokes proxy of OrderPaymentService
    }
}

@Service
public class OrderPaymentService {
    private final PaymentClient paymentClient;
    private final OrderRepository orderRepository;

    public OrderPaymentService(PaymentClient paymentClient, OrderRepository orderRepository) {
        this.paymentClient = paymentClient;
        this.orderRepository = orderRepository;
    }

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void executePayment(Order order) {
        paymentClient.charge(order.getCustomerId(), order.getAmount());
        order.setStatus(OrderStatus.CONFIRMED);
        orderRepository.save(order);
    }
}

💻 3. Code Challenge
import org.springframework.stereotype.Service; import org.springframework.transaction.annotation.Transactional; @Service public class BankingTransferService { private final AccountRepository accountRepository; private final AuditService auditService; public BankingTransferService(AccountRepository accountRepository, AuditService auditService) { this.accountRepository = accountRepository; this.auditService = auditService; } @Transactional public void transferFunds(Long fromId, Long toId, BigDecimal amount) throws AuditFailedException { accountRepository.debit(fromId, amount); accountRepository.credit(toId, amount); // Throws checked AuditFailedException extends Exception auditService.recordTransfer(fromId, toId, amount); } }
🎯 Answer Quality:
Not Rated
Answer Key & Deep-Dive Explanation

Root Cause: Spring's transaction interceptor follows the EJB convention: checked exceptions represent anticipated business recovery conditions, so the transaction is committed by default. Only unchecked exceptions (subclasses of RuntimeException) or JVM Errors trigger an automatic rollback.

Because AuditFailedException extends Exception (a checked exception), Spring commits the transaction despite the exception escaping the method.

Recommended SolutionJava
// Fix 1: Explicitly specify rollbackFor on the annotation
@Transactional(rollbackFor = Exception.class)
public void transferFunds(Long fromId, Long toId, BigDecimal amount) throws AuditFailedException {
    accountRepository.debit(fromId, amount);
    accountRepository.credit(toId, amount);
    auditService.recordTransfer(fromId, toId, amount);
}

// Fix 2: Preferred Clean Architecture - Use Unchecked Business Exceptions
public class AuditFailedException extends RuntimeException {
    public AuditFailedException(String message, Throwable cause) {
        super(message, cause);
    }
}

🎯 Answer Quality:
Not Rated
Answer Key & Deep-Dive Explanation

Root Cause: In constructor injection, the JVM requires all arguments to be instantiated before invoking the constructor. Spring cannot create UserService without an existing AuditService, and cannot create AuditService without an existing UserService.

    }

@Service
public class AuditService {
    private final AuditLogger auditLogger;

    public AuditService(AuditLogger auditLogger) {
        this.auditLogger = auditLogger;
    }
}

// Temporary Workaround (Avoid as long-term solution):
@Service
public class UserService {
    private final AuditService auditService;

    public UserService(@Lazy AuditService auditService) {
        this.auditService = auditService;
    }

🎯 Answer Quality:
Not Rated
Answer Key & Deep-Dive Explanation

Root Cause: Without @ConditionalOnMissingBean, the starter's bean definition unconditionally registers into the ApplicationContext.     @ConditionalOnMissingBean(SecurityService.class)
    public SecurityService securityService() {
        return new DefaultSecurityService();
    }
}

1. WHAT is a Spring Boot Profile:
A Profile is a first-class Spring core feature that conditionally segregates beans, services, and configuration properties so they are activated only in specific target environments (e.g., local, dev, qa, staging, prod).

2. WHY Profiles are essential in Enterprise Microservices:

  • Environment Isolation: Avoids hardcoded environmental parameters. A single packaged JAR artifact can be deployed unchanged across local laptop, CI/CD pipeline, staging, and production.
  • Service Mocking vs Real Gateways: In dev, inject mock beans (e.g. ConsoleEmailService, in-memory H2 database). In prod, inject real beans (e.g. AwsSesEmailService, clustered MySQL Aurora).

  • Property File Resolution:
    Spring Boot first loads base defaults from application.yml, then overlays and overrides keys using the active profile document: application-{profile}.yml.

Approach 1 (Recommended): spring.config.import (Spring Boot 2.4+)YAML
# Inside the classpath application.yml:
spring:
  config:
    # 'optional:' prevents application crash if running locally without this file

# import: "optional:file:/etc/config/"

java -jar app.jar

# --spring.config.additional-location: Overlays external config on top of internal classpath defaults.

import org.springframework.context.annotation.Configuration;
import org.springframework.context.annotation.PropertySource;
import org.springframework.beans.factory.annotation.Value;

@Configuration
// 'file:' prefix instructs Spring ResourceLoader to read from external filesystem, not classpath!
@PropertySource(value = "file:/etc/config/app.properties", ignoreResourceNotFound = true)
public class ExternalConfig {

    @Value("${custom.external.timeout:5000}")
    private int externalTimeout;

    public int getExternalTimeout() {
        return externalTimeout;
    }
}

  1. Command-line arguments (--server.port=9090)
